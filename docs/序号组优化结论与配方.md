# 序号组优化 —— 结论与生产配方（2026-06-23 定稿）

四线 T9EST188 真实案例:人工 47 序号组,生产系统 55,得率相同。本轮把求解器从 **55 压到 47-50（确定、无伪解、得率不变）**,并彻底搞清了机理与天花板。

## 一、机理(三层,全部实验验证)

1. **杠杆 = B 层装配,不是 A 层选型。** 三次实验证伪"花型集是杠杆":把人工花型集喂我的装配仍得 55(=我自己花型集)。序号组的差距在「订单→槽位、跨车怎么同质化」,不在选哪些花型。
2. **A 层分布值 ~5 组,但只在人工特定花型上兑现。** 人工花型 patternWidth 摊匀(像正态分布),我的堆在 4400(废边最低)。但实测「机械去集中化」重选(min 车数@pw≥4390,得率中性)反而 pre-LNS 更差(56)、LNS 后仍 47——**人工的"均衡"是隐性的"可装配性",非简单分布形状,简单目标复制不出。**
3. **确定性 = SCIP 节点界,不是 CP-SAT。** 富列池非确定的根因是 wall-clock 时限(机器快慢→不同 incumbent)。改用 `limits/nodes` 固定节点数→incumbent 完全可复现,即使没证到 OPTIMAL。**绕开了"富池解不到 OPTIMAL"死结,不需升 9.11**(9.11 还回退 t9est 76→84)。

## 二、可交付结果

| 配置 | 序号组(四线) | 确定性 | 备注 |
|---|---|---|---|
| 生产现状(无LNS) | 55 | 确定 | 基线 |
| LNS 默认(非enrich) | ~49-50 | ✅ 节点界确定 | 省 5-6 组,较快 |
| LNS + enrichPatterns | ~47-48 | ✅ | 追平人工,较慢 |
| (人工花型 + enriched LNS) | 42-43 | —— | 仅证明 enriched LNS 在人工花型上能超人工;不可从零复现 |

**全部 over=0、废边不变(得率分毫不动)、逐(宽度|消息)产量守恒(无伪解,有硬断言)。**

## 三、生产配方

LNS **默认关闭**(`cutting.lns.enabled` 默认 false),生产路径不变。启用即得确定结果:

```
-Dcutting.lns.enabled=true            # 开启 LNS
-Dcutting.lns.secondary=false         # 关 stage2 二级目标(更快/更确定,不改组数地板)
-Dcutting.lns.enrichPatterns=true     # 花型池补中间 patternWidth(冲 47-48;不开则 ~49-50)
# 以下已是默认,无需指定:
# scipNodeLimit=15000  (确定性节点界,默认开)
# timeLimitMs=120000   (wall-clock 兜底,只防跑飞)
# maxColumnsPerPattern=1000 (非enrich不限;enrich 时设 10-12)
```

**速度/质量旋钮**:`scipNodeLimit`↑、`maxFreeOrders`↑、`enrichCap`↑ → 更低组数但更慢。大邻域(maxFreeOrders≥14)能把组数再压但很慢,不建议生产默认。

## 四、天花板与未达

- **现实天花板 ≈ 47-48(匹配人工)**,确定可交付。
- **43(碾压人工)不可由简单方法复现**:需要人工那种隐性的"可装配性"花型选择,超出当前可建模范围。43 只在直接喂人工花型集时出现。
- **CP-SAT/9.11 此路不通**:9.11 回退 t9est 76→84。9.10 + SCIP 节点界已足够确定。

## 五、关键代码

- `LocalNeighborhoodSequenceOptimizer`:确定性迭代界停止、SCIP 节点界、stage2 开关、花型 enrichment(`generateBalancingPatterns`,按 patternWidth band/均匀采样/列池按花型封顶)。
- `InstructionConverter.arrangeForSequenceGroups`:候选计组前统一 compact+reorder(防假分裂)。
- 基准夹具:`B5SixianTest`(真实四线案例 + 硬防伪解断言 + 人工花型/去集中对照诊断)。
