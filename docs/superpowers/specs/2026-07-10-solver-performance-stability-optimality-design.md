# 求解性能、稳定性与最优性研究设计

## 1. 背景

当前质量模式已经能够在固定车数和废边的前提下达到以下结果：

| 数据集 | 序号组 | 奇数车组 | 小车数组 | 总车数 | 总废边 |
| --- | ---: | ---: | ---: | ---: | ---: |
| sixian | 42 | 2 | 12 | 462 | 102,240 mm |
| t9est188 | 66 | 8 | 26 | 530 | 119,670 mm |

现有日志表明，结果质量已经进入可用区间，但求解时间仍有明显波动：

- sixian 的 42 组结果约为 253 至 503 秒。
- t9est188 的 66 组结果约为 734 至 1494 秒。
- Stage5 已使用固定节点上限，当前主要长尾转移到了 LNS 和 SPR。
- LNS 与 SPR 使用公共并行线程池；并发请求或系统负载会影响墙钟时间。
- SPR 对单个子问题使用 20/40 秒墙钟上限，对整段使用 300 秒墙钟上限。
- 日志中存在多个线程重复求解相同规模残差问题的现象。

本轮工作的目标不是通过缩短搜索换取速度，而是在守住当前质量基线的前提下消除重复计算、非确定停止和潜在漏解，再继续寻找更优解及其最优性证据。

## 2. 目标与硬约束

### 2.1 质量硬门槛

任何生产默认方案必须同时满足：

1. sixian 不劣于 `42/2/12`。
2. t9est188 不劣于 `66/8/26`。
3. 总车数不得增加。
4. 总废边不得增加。
5. 需求守恒、工位分配和超产约束不得退化。
6. 快解路径结果与耗时不得受到质量模式实验影响。

质量比较继续采用现有字典序：

`车数 -> 序号组 -> 奇数车组 -> 小车数组 -> 花型数 -> 废边/超产`

如果发现隐藏缺陷，允许并鼓励得到少于 42 或 66 组的结果，但不能通过放宽车数、废边或需求守恒获得。

### 2.2 性能目标

第一阶段目标：

| 数据集 | P50 目标 | P95 目标 | 同机波动目标 |
| --- | ---: | ---: | ---: |
| sixian | 不高于 4.2 分钟 | 不高于 5 分钟 | 不高于 15% |
| t9est188 | 不高于 10 分钟 | 不高于 12 分钟 | 不高于 15% |

性能目标是研究方向，不覆盖质量硬门槛。未达到性能目标但保持质量的方案可以继续研究；任何质量退化方案直接淘汰。

### 2.3 最优性目标

逐步建立三层结论，禁止把“当前最好”描述成“全局最优”：

1. **可行上界**：当前已知最好的序号组结果。
2. **列池内最优**：在已生成完整列池中证明最优，并报告 MIP 状态和 gap。
3. **问题全局最优**：只有列生成/枚举完整性得到证明，且整数模型 gap 为 0 时才能声明。

## 3. 当前链路与问题定位

生产链路为：

`前端或 APS 请求 -> OptimizationExecutionService -> SolverRuntimeProperties -> CuttingSolver -> A 层花型选择 -> Stage5 -> LNS -> SPR -> InstructionConverter -> 求解报告`

当前主要问题分为四类。

### 3.1 缺少阶段级性能证据

求解报告只有整组耗时，不能稳定区分 A 层、Stage5、两套 LNS 变体、SPR 两个阶段及候选跳过的耗时和调用次数。后续调优必须先补齐阶段指标，否则容易把机器负载波动误判为算法改进。

### 3.2 重复子问题求解

LNS 和 SPR 会从不同目标或邻域生成相同的残差需求、车数、废边和候选列。当前按目标逐个提交 SCIP，缺少规范化签名和请求内缓存。相同子问题被重复求解不会增加搜索覆盖，只增加耗时。

### 3.3 停止条件仍受墙钟影响

Stage5 和 LNS 已有节点上限，但 SPR 的 `PARITY_BUDGET_MS`、`MERGE_BUDGET_MS` 和总预算仍以墙钟为主。墙钟既受 CPU 频率、操作系统调度影响，也受公共线程池中的其他任务影响，因此同一输入可能完成不同数量的有效搜索。

### 3.4 经验剪枝存在潜在漏解风险

`skipGapThreshold=8` 根据历史样本判断候选是否值得进入 SPR。该阈值目前没有可证明的候选下界支撑，因此只能称为经验剪枝，不能满足“保证结果”的要求。

这不代表该阈值已经造成已知错误，但它是本轮必须证伪的隐藏风险。生产质量模式不能仅凭候选当前落后组数永久跳过可能追平或反超的候选。

## 4. 方案比较

### 方案 A：证据驱动的无损优化，推荐

先建立阶段计时和重复求解统计，再实施请求内去重、结果缓存、独立有界执行器和确定性停止条件。质量门禁由自动化基准保护，所有改动逐项 A/B。

优点：风险最低，能够定位真实收益，大部分优化不改变搜索空间。

缺点：需要先投入一轮观测与基准建设，不能立即大幅改写模型。

### 方案 B：继续压缩参数和墙钟预算

继续降低 LNS 邻域数、SPR 预算和候选阈值，以更少搜索换取速度。

优点：实现快，短期耗时下降明显。

缺点：容易截断产生 42/66 组结果的接受链，不能满足质量硬门槛，因此只作为对照实验，不作为生产方案。

### 方案 C：直接迁移为全局 CP-SAT/完整 set-partition

一次性将 Stage5、LNS、SPR 合并为更大的全局整数模型，尝试直接证明最优。

优点：理论目标最完整，有机会输出严格 gap。

缺点：列空间和配置空间巨大，迁移成本高；在没有性能基线和完整列策略前，可能比现有方案更慢且更难调试。

本设计选择方案 A，并把方案 C 作为第三阶段研究支线。

## 5. 实施设计

### 5.1 阶段一：基准与可观测性

为每个 groupKey 记录以下指标：

- A 层候选数量、各候选耗时和状态。
- Stage5 调用次数、节点数、状态和耗时。
- 默认 LNS 与扩大 LNS 的迭代数、邻域数、缓存命中数、节点数、改善轨迹和耗时。
- SPR parity/merge 的迭代数、目标数、唯一子问题数、缓存命中数、接受次数和耗时。
- 每个候选从 Stage5 到最终结果的 `组/odd/small` 变化。
- 求解器线程数、有效并行度和安全墙钟是否触发。

新增指标只能记录数据，不改变候选选择与求解行为。第一轮重复基准用来形成改动前基线。

### 5.2 阶段二：无损提速

#### 子问题规范化

为 LNS/SPR 子问题构造不可变规范化键，至少包括：

- 排序后的残差需求键及数量。
- 精确车数。
- 精确废边或废边上限。
- 排序去重后的候选列签名。
- 目标权重和影响可行域/目标函数的运行参数。

同一个请求、同一个求解阶段内，相同键只允许实际调用一次 SCIP。其他调用复用不可变结果副本。

#### 目标去重

在进入并行求解前，先按“拆除块集合 + 规范化子问题键”合并等价目标。归并后仍按原有稳定顺序评优，保证选择结果不因并行完成顺序变化。

#### 独立有界执行器

LNS 和 SPR 不再直接使用 `parallelStream()` 及 JVM 公共线程池。每次请求使用受控执行器：

- 并行度从可用核心数和并发请求上限计算。
- 单个 SCIP 子问题保持单线程。
- 任务提交顺序和结果归并顺序固定。
- 请求结束必须关闭执行器，不泄漏线程和缓存。

该改动解决 APS 并发请求互相抢占公共线程池的问题，也便于记录实际并行度。

### 5.3 阶段三：稳定停止条件

稳定性遵循“确定性预算决定搜索，墙钟只负责安全兜底”：

- Stage5 继续使用固定节点上限。
- LNS 保持固定迭代、固定邻域顺序和固定 SCIP 节点上限。
- SPR 子问题增加可校准的节点上限，替代 20/40 秒作为主要决策条件。
- SPR 总体采用固定迭代数、固定唯一子问题数或固定累计节点数停止。
- 墙钟只作为异常情况下的安全上限；触发安全上限的结果必须在报告中标记为稳定性风险，不能静默当作正常基准。

节点预算通过 sixian/t9est188 扫描确定。每次只调整一个参数，结果不满足质量门槛立即回退。

### 5.4 阶段四：安全候选筛选

先将 `skipGapThreshold` 从生产正确性条件降级为实验开关。生产质量模式只允许两类跳过：

1. 子问题与已求解问题等价，直接复用结果。
2. 存在可验证下界，证明该候选即使达到下界也不可能优于当前最好结果。

如果暂时构造不出足够强的安全下界，则保留候选并依靠去重、缓存和确定性预算提速，不能以经验阈值宣称零风险。

候选下界研究优先考虑：

- 需求配置连通分量下界。
- 不可合并消息/宽度冲突形成的最小块覆盖下界。
- 当前花型族奇偶性带来的 odd 下界。
- 已固定车数和废边下可激活列数的 LP/MIP 松弛下界。

### 5.5 阶段五：逼近与证明最优

在不影响生产路径的研究模式中建立“全局列档案”：

- 收集 A 层、Stage5、LNS、SPR 发现的所有守恒列。
- 对列签名去重，并记录来源、首次发现轮次和是否进入最优解。
- 在固定车数和废边条件下执行全局字典序 set-partition。
- 保存 incumbent、best bound、gap、节点数和证明状态。

研究分两步：

1. 先证明“当前列池内最优”，用于发现现有局部搜索是否还遗漏列组合。
2. 再研究定价或受控完整枚举，缩小“列池内最优”和“原问题全局最优”的差距。

只有当完整列生成条件得到证明时，才评估将该研究模型迁移到 CP-SAT。CP-SAT 不是第一阶段提速手段，而是确定性和最优性证明的架构候选。

## 6. 隐性缺陷处理原则

优化过程中发现问题时按以下顺序处理：

1. 用最小数据或现有基准复现。
2. 确认问题位于入口参数、候选生成、子问题建模、结果验收还是并行归并。
3. 增加失败测试，证明修复前会漏解、摇摆或重复求解。
4. 实施单一根因修复。
5. 同时验证质量、守恒、耗时和稳定性。

允许修复带来更少序号组，但禁止通过修改评价顺序掩盖 odd、小车组、车数或废边退化。

## 7. 验证方案

### 7.1 自动化测试

- 运行全部 `*Test.java`，报告实际执行数、成功数和失败数。
- 为规范化键、等价目标去重、缓存隔离、稳定归并、请求级执行器关闭增加单元测试。
- 为质量档位从 UI 和 APS 两个入口进入同一运行参数增加链路测试。
- 为经验剪枝禁用或安全下界判断增加回归测试。

### 7.2 性能实验

实验固定以下条件：

- 同一台机器、同一 JDK 和 OR-Tools 版本。
- 求解期间不并行运行其他基准。
- 每个候选方案先运行 sixian/t9est188 各 3 次。
- 进入最终候选后各运行 5 次，记录 P50、P95、最小值、最大值和变异系数。
- 每次保存阶段指标、最终质量和结果签名。

### 7.3 验收矩阵

| 检查项 | 必须满足 |
| --- | --- |
| sixian | 每次均不劣于 42/2/12 |
| t9est188 | 每次均不劣于 66/8/26 |
| 车数/废边 | 与基准一致或更优 |
| 需求守恒 | 完全一致 |
| 快解 | 结果不回退，性能无明显下降 |
| 重复求解 | 唯一子问题数下降，缓存命中可解释 |
| 稳定性 | 相同配置的搜索计数和结果签名一致；墙钟波动达标 |
| 最优性 | 明确区分可行上界、列池内最优和全局最优 |

## 8. 交付顺序

1. 提交基准与阶段指标。
2. 提交等价子问题去重和请求内缓存。
3. 提交独立有界执行器。
4. 提交确定性 SPR 预算和安全候选筛选。
5. 提交全量回归与重复基准结论。
6. 单独提交最优性研究模型和实验结论。

每一步都必须能够独立回退；只有通过质量门槛和实际测试数验证后，才进入下一步。

## 9. 明确不做

- 不通过减少候选、缩短墙钟或降低节点数直接替换生产默认值。
- 不在第一阶段重写整个求解器或直接迁移 CP-SAT。
- 不改变车数、废边、需求守恒和业务评价顺序。
- 不把单次最好耗时作为稳定性能结论。
- 不把列池内最优误报为原问题全局最优。
