# DJX188 生产中性移动闭环实验设计

## 1. 背景与已确认事实

DJX188 当前自动方案和人工方案在逐宽幅产量、总车数和总废料上完全一致，但最终序号组结构不同：

| 方案 | 花型数 | 总车数 | 总废料 | 兼容性最小组数 | 额外拆分 | 奇数组 | 单车组 |
|---|---:|---:|---:|---:|---:|---:|---:|
| 人工方案 | 26 | 169 | 36870 | 26 | 0 | 1 | 0 |
| 中间态25 | 25 | 169 | 36870 | 26 | 1 | 1 | 0 |
| 中间态24 | 24 | 169 | 36870 | 27 | 3 | 1 | 0 |
| 自动方案 | 22 | 169 | 36870 | 28 | 6 | 1 | 0 |

现有证据已经证明：

- 给定花型集合后，使用次数由精确产需矩阵唯一确定，批次不是独立缺口；
- parity-kernel 可以解释和约束花型使用次数的奇偶结构；
- order-compatibility kernel 可以精确证明给定花型使用方案的最小序号组数；
- 目标不能简化成花型数最小化，正确的集合级指标是“花型数 + 兼容性额外拆分”；
- 中间态24/25是引用人工端点构造的诊断样本，不能作为生产搜索信号；
- 当前自动22方案需要从完整候选宇宙中自主重组支持集，而不是继续压缩花型数。

本轮从自动22方案出发，不读取人工花型签名、人工使用次数或到人工方案的距离，验证生产中性整数移动能否自主把兼容性最小组数从28降到27。

## 2. 目标与非目标

### 2.1 首轮目标

在DJX188固定数据上寻找新使用向量 `x'`，满足：

```text
逐宽幅精确满足需求
总车数 = 169
总废料 = 36870
超产 = 0
花型使用层：奇数使用次数 = 1，使用次数为1的花型 = 0
最终配置组层：序号组数 <= 27，奇数组 = 1，单车组 = 0
```

若找到候选，必须由完整订单配置阈值MIP证明其最终配置组层条件，再运行完整 `OrderCompatibilityKernelAnalyzer` 确认精确最小组数和拆分见证。

### 2.2 非目标

- 不接入生产bundle生成、列生成、Stage4、Stage5、Phase2或LNS；
- 不修改页面、接口、Excel链路或打包配置；
- 不以人工方案为搜索目标或评分参照；
- 不构造全局零空间基底、Graver基或宣称全局邻域完备；
- 不允许通过临时增加奇数、单车或兼容性组数来换取后续改善；
- 不把兼容性拆分责任固化成可相加的单花型静态罚分；
- 首轮不要求一步达到人工26组，只验证28到27的自主改进能力。

## 3. 两层奇偶语义

本轮必须严格区分两个数学对象。

### 3.1 花型使用层

`x[p]` 表示花型 `p` 的总使用车数。移动生成器中的奇偶约束只作用于 `x[p]`：

```text
x[p] = 2 * half[p] + odd[p]
sum(odd[p]) = 1
x[p] = 0 或 x[p] >= 2
```

该约束是廉价必要条件，用于避免生成明显不符合目标的使用向量。

### 3.2 完整订单配置组层

`count[p,c]` 表示花型 `p` 的完整订单配置 `c` 使用多少车。最终用户指标作用于这些配置组：

```text
groups = count(count[p,c] > 0)
oddGroups = count(count[p,c] 为正奇数)
oneGroups = count(count[p,c] = 1)
```

即使 `x[p]` 为偶数，它仍可能被拆成两个奇数配置组；即使 `x[p] >= 2`，其中一个配置组仍可能只有1车。因此花型使用层条件不能替代最终配置组层判定。

## 4. 搜索状态与生产中性不变量

完整候选宇宙记为 `U`，由现有 `CompletePatternEnumerator` 在DJX188固定生产域内确定性生成，当前基线为整数使用向量 `x`。

每个花型 `p` 的宽幅系数向量记为 `A[p]`。合法移动 `delta` 必须满足：

```text
A * delta = 0
sum(delta[p]) = 0
0 <= x[p] + delta[p] <= upper[p]
```

因此应用移动后的方案自动保持逐宽幅产量和总车数。候选仍要显式复核总废料36870和零超产，避免未来生产域或废料定义变化后依赖隐含等价关系。

状态使用完整规范化使用向量签名去重，而不是按移动表达式去重。不同回路、不同移出/移入表达式若得到相同 `x'`，只评价一次。

## 5. 方案比较与选择

### 5.1 全局有理零空间或Smith标准形基底

优点是可以描述整个整数核空间。缺点是DJX188完整矩阵零空间维度约7688，标准基底通常稠密；对基底系数做小范围枚举既不完整，也不保证能优先得到稀疏小移动。

本轮不采用。

### 5.2 全局电路或Graver基枚举

理论表达力最强，但在7717列规模下不可执行，无法在工程预算内完成枚举和证明。

本轮不采用。

### 5.3 分层有界完备（采用）

第一层完整穷尽固定当前状态的一步单位2对2移动；第二层使用有界稀疏MIP覆盖任意系数和每侧最多3个不同花型，并明确报告是否真正穷尽。该方案牺牲全局完备性，换取可执行、可解释和可度量的局部证明力。

## 6. 第一层：完整单位2对2枚举

### 6.1 数学定义

单位2对2关系为：

```text
P_i + P_j = P_k + P_l
```

花型对是多重集合，允许 `i = j` 或 `k = l`。对应单位移动为：

```text
delta = -multiset(P_i, P_j) + multiset(P_k, P_l)
```

移动可以统一缩放：

```text
x' = x + t * delta
t = 1, 2, ..., tMax
```

### 6.2 完整补集查找

任何从当前状态出发的可行一步移动，其净移出花型必然位于当前支持集。因此只枚举当前支持集的移出多重集合对，再在完整宇宙中查找移入补集：

1. 对当前支持集枚举 `i <= j`；
2. 计算精确向量和 `S = A[i] + A[j]`；
3. 遍历宇宙中的 `k`，计算所需补向量 `A[l] = S - A[k]`；
4. 通过花型系数向量哈希索引取得全部 `l`；
5. 使用规范顺序消除 `k,l` 对称重复。

该方法不预存约3000万全局花型对，但不会漏掉固定当前状态的一步单位2对2移动。

### 6.3 规范化与倍数边界

移出和移入侧出现同一花型时先抵消，拒绝零移动。令：

```text
negative[p] = max(-delta[p], 0)
positive[p] = max(delta[p], 0)
```

在变量域 `0 <= x[p] <= upper[p]` 下：

```text
tMax = min(
  min floor(x[p] / negative[p])               for negative[p] > 0,
  min floor((upper[p] - x[p]) / positive[p]) for positive[p] > 0
)
```

当前169车模型中正向上界通常由总车数不变和非负性隐含保证，但实现保留完整公式。必须枚举 `1..tMax` 的每个整数，不能只测试最大倍数，因为中间倍数可能具有不同的奇偶和订单兼容性结构。

### 6.4 完整性边界

“第一层已穷尽”严格表示：

> 在固定候选宇宙、固定当前使用向量和固定变量上下界下，所有一步单位2对2移动及其全部可行统一倍数均已枚举。

它不表示任意系数2对2、多步路径、每侧3个以上花型或全局整数核空间已被穷尽。每当严格改善状态成为新基线时，必须从新状态重新完整枚举第一层邻域。

### 6.5 第一层诊断指标

每个搜索状态至少输出：

- 当前支持集大小和移出对数量；
- 补集扫描次数、补集命中数和原始回路数；
- 抵消后的零移动数、规范化移动数和重复移动数；
- `tMax`分布、倍数展开候选数和最终状态去重数；
- 生产不变量失败数、使用层奇偶失败数；
- 单步枚举耗时和累计枚举耗时。

## 7. 第二层：每侧最多3个花型的稀疏MIP

### 7.1 变量与约束

对每个花型 `p` 定义：

- `remove[p]`：从当前状态净移出的整数车数；
- `add[p]`：向当前状态净加入的整数车数；
- `removeSelected[p]`、`addSelected[p]`：对应侧是否使用该花型；
- `next[p] = x[p] - remove[p] + add[p]`；
- `active[p]`：`next[p]`是否为正；
- `half[p]`、`odd[p]`：使用层奇偶分解变量。

核心约束：

```text
A * (add - remove) = 0
sum(add - remove) = 0
1 <= sum(removeSelected) <= 3
1 <= sum(addSelected) <= 3
removeSelected[p] + addSelected[p] <= 1
```

激活联动在模型第一阶段完整加入：

```text
removeSelected[p] <= remove[p] <= x[p] * removeSelected[p]
addSelected[p] <= add[p] <= (upper[p] - x[p]) * addSelected[p]
2 * active[p] <= next[p] <= upper[p] * active[p]
next[p] = 2 * half[p] + odd[p]
sum(odd[p]) = 1
```

这复用现有兼容性核已验证的“选择变量下界联动”原则，禁止出现选择变量为1而整数数量为0的弱松弛，也禁止 `next[p] = 1`。

### 7.2 支持集与系数两级枚举

第二层不在一个大模型中直接逐个排除完整7717维使用向量，而采用：

1. 主MIP寻找一个可行的有符号支持集及一组可行系数；
2. 固定该支持集后建立最多6个非零整数系数的小型子MIP；
3. 子MIP枚举该支持下所有合法系数组合，并按最终 `x'` 去重；
4. 子MIP穷尽后，向主MIP加入支持集no-good cut；
5. 继续寻找下一组支持，直到证明无剩余支持或触及时间、支持数量、候选数量上限。

固定支持子问题中的精确系数no-good cut必须表达“至少一个系数与当前解不同”，不能只排除支持集合，否则会漏掉同一支持下不同整数系数产生的不同奇偶和兼容性状态。

### 7.3 与第一层的关系

第二层允许每侧1、2或3个不同花型，因此自然包含任意系数2对2、1对2、2对1和真正的3对3。第一层已产生的最终状态通过全局状态签名缓存去重。第二层允许重新发现第一层表达式，但不得重复运行昂贵评价。

### 7.4 动态兼容性反馈

现有 `OrderCompatibilityKernelAnalyzer.Analysis.splitWitnesses` 提供被拆花型、完整配置、变化宽幅和相关订单消息。该见证只用于主MIP的目标排序或候选优先级：

- 优先触及当前拆分见证涉及的花型集合和宽幅；
- 优先探索能改变当前冲突连接关系的移入花型；
- 不把见证转化成永久单花型罚分；
- 不把见证作为硬约束，因此不会破坏第二层本身的可行域；
- 基线或平台状态变化后重新运行兼容性核并重建见证排序。

### 7.5 第二层完成状态与指标

完成状态定义为：

- `EXHAUSTED`：主MIP证明无未访问支持，且所有固定支持子问题均已穷尽；
- `TIMED_OUT`：总时间或当前MIP时间到达上限；
- `CAPPED`：支持数量或最终状态数量达到显式上限；
- `PARTIAL`：主MIP仍可继续，但至少一个固定支持子问题未完成；
- `SOLVER_UNAVAILABLE`或`ABNORMAL`：求解器不可用或异常。

必须输出：

- 主MIP每轮状态、耗时、节点数和best bound；
- 已访问支持数、支持no-good cut数及每轮增量耗时；
- 固定支持子问题数、已穷尽数、超时数和系数no-good cut数；
- 原始解数、第一层重复数、最终状态去重数；
- 生产不变量和使用层奇偶校验结果；
- 触及各类上限的具体原因。

所有时间和数量预算通过研究侧 `Options` 显式传入并原样打印。预算只影响完成状态，不改变“已穷尽”的语义。

## 8. 分层评价与严格状态语义

### 8.1 廉价校验

每个候选先验证：

- 非负整数和真实变量上界；
- 逐宽幅精确产需；
- 169车、36870废料、零超产；
- 使用层奇数次数为1；
- 使用次数为1的花型数为0。

失败候选直接拒绝，并记录失败原因。

### 8.2 快速可行上界

现有Stage5/Phase2研究入口可用于生成最终组数的快速可行上界和候选排序：

- 若快速路径得到不超过27组且组层奇数1、单车0的完整可行方案，它已经证明该候选达到首轮目标；
- 快速路径结果较差或失败不能证明候选不可达27，因此不能作为安全淘汰依据；
- 快速路径只影响精确评价顺序，不改变候选的数学状态。

### 8.3 完整配置阈值MIP

在测试侧为 `OrderCompatibilityKernelAnalyzer` 增加阈值判定入口，复用现有完整配置枚举和激活联动，直接询问：

```text
是否存在完整订单配置分配，使得：
sum(active[p,c]) <= targetGroups
sum(odd[p,c]) = 1
sum(one[p,c]) = 0
```

其中仍保持每花型总使用次数和每笔订单需求精确相等。

状态解释：

- 找到可行解：证明候选满足目标，不要求先证明目标函数最优；
- `INFEASIBLE`：证明该候选在给定阈值和组层形态下不可行；
- 超时且未找到解：`UNKNOWN`，不得解释为不可行；
- 配置枚举超限或求解器异常：单独报告，不得静默过滤。

找到27组可行候选后，再运行完整三阶段兼容性分析器，确认精确最小组数、额外拆分、奇数组、单车组和拆分见证。

阈值判定还必须覆盖平台状态的身份确认。以当前最优值28为例：

- `targetGroups = 27` 可行：该候选是严格改善候选；
- `targetGroups = 27` 已证明不可行，且 `targetGroups = 28` 可行：该候选才可被认定为28组平台状态；
- 27阈值未知但28阈值可行：该候选仍可能是严格改善，记为待判定状态，不能直接归入平台队列；
- 27阈值已证明不可行但28阈值也不可行：该候选严格差于当前最优值，拒绝；
- 任一关键阈值超时且无替代证明：保持 `UNKNOWN`，不得扩展其邻域。

快速路径若给出满足组层形态的28组完整方案，可以作为“28可行”的证明；但“27不可行”仍只能来自阈值MIP的不可行证明或完整精确分析。因此同分平台搜索不会把29组以上状态误当成28组状态。

### 8.4 两种“穷尽”必须分开

- `moveGenerationExhausted`：移动空间按当前层定义已完整生成；
- `exactEvaluationExhausted`：每个需要判定的唯一候选都得到阈值可行、阈值不可行或安全数学过滤结论。

如果移动已全部生成，但仍有超时未知候选，只能报告“移动生成已穷尽、精确评价未穷尽”，不能宣称该邻域不存在27组方案。

## 9. 搜索与接受策略

基线目标值为：

```text
G(x) = supportCount(x) + compatibilityExtra(x) = exactMinimumGroups(x)
G(auto22) = 28
```

首轮策略：

- `G < currentBest`：严格改善，成为新基线；
- `G = currentBest`：只有在严格改善阈值已证明不可行、当前最优阈值已证明可行后，才可以进入有容量和深度限制的平台探索队列，但不报告为改进；
- `G > currentBest`：拒绝；
- `G` 尚未被阈值证据定界：保留为待判定记录，不进入邻域扩展；
- 使用层或最终组层的奇数/单车条件退化：拒绝；
- 不使用概率接受、模拟退火、禁忌退化预算或先坏后好的路径。

平台队列按完整状态签名去重，并记录父状态和移动见证。严格改善状态出现后，清理不再相关的较差平台状态，从新基线重新完整枚举第一层；若第一层无改进，再启动第二层。

平台容量、最大深度和精确评价预算属于实验参数，必须输出实际值。触及限制后只能报告有界搜索结果，不能宣称多步平台路径已全局穷尽。

## 11. 测试设计

### 11.1 第一层枚举器

- 小型宇宙与暴力全花型对枚举逐项对照，证明补集查找无遗漏；
- 覆盖 `i=j`、`k=l` 的多重集合情况；
- 覆盖移入/移出重叠后的抵消和零移动拒绝；
- 覆盖通用正负上界下的 `tMax`；
- 断言 `1..tMax` 全部生成而不是只生成最大倍数；
- 断言不同表达式得到同一最终状态时只保留一次。

### 11.2 第二层稀疏MIP

- 覆盖任意系数2对2、1对2、2对1和3对3；
- 断言每侧不同花型数不超过3；
- 断言激活变量与正整数系数双向联动；
- 断言使用层奇数1、使用次数1为0；
- 断言固定支持下不同系数组合不会被支持no-good误删；
- 覆盖 `EXHAUSTED`、`TIMED_OUT`、`CAPPED`、`PARTIAL` 状态边界；
- 核对支持no-good和系数no-good计数。

### 11.3 奇偶层级反例

构造一个花型使用次数为3的简单精确方案，订单配置必须拆成1车和2车两个配置组。该方案满足使用层“奇数1、使用次数1为0”，但最终配置组层存在一个单车组。

阈值接口必须拒绝 `oneGroups = 0` 的请求。该测试防止以后再次把使用层奇偶误当成组层奇偶。

### 11.4 兼容性核回归

新增阈值回归至少覆盖“可行”“已证明不可行”“超时未知”三种语义。
