# DJX188 支持分桶评价控制实验设计

## 1. 背景与当前证据

结构化局部花型宇宙实验已经完成三层候选范围构造，并在同一条研究链路中形成：

```text
三层局部宇宙
  -> 稀疏生产中性支持搜索
  -> 系数状态生成
  -> Phase2 快速可行上界
  -> 订单兼容性阈值 MIP
```

最近一次受限运行从三个局部层合并得到 307 个唯一使用状态。现有实验先按状态和支持做一次静态多样化，只对前 30 个状态运行 Phase2，再把 Phase2 排名前 5 的状态送入精确阈值 MIP。结果没有找到 27 组，但该结论仍为 `INCONCLUSIVE`，原因包括：

1. 三层支持搜索都因时间预算停止，没有穷尽；
2. 同一有符号支持下的多个系数状态可能挤占或错失有限评价名额；
3. 当前候选顺序在 Phase2 之前并不知道哪个系数状态更好；
4. 精确 MIP 预算按全局状态排名分配，可能重复评价同一支持；
5. 支持主 MIP 已能分支，但大量主问题目标值停留在相同水平，说明“能启动”与“目标是否具有区分度”是两个独立问题。

本轮冻结候选生成侧，只替换研究侧评价和预算分配方式，用单变量控制实验区分：候选是否已经生成但被漏选、支持是否选对但系数状态选错，以及当前 Phase2 代理是否根本没有给出更强信号。

## 2. 目标与研究问题

本轮回答四个问题：

1. 在同一次稀疏搜索实际生成的唯一状态中，全量 Phase2 能找到的最好可行上界是多少？
2. 当前前缀抽样是否遗漏了 Phase2 评价更好的支持或系数状态？
3. 在完全相同的全量 Phase2 结果、精确 MIP 次数和单次时间预算下，按支持分桶分配精确预算是否优于按状态全局排名？
4. 大量相同主 MIP 目标值是否与低支持覆盖、同支持系数拥挤或 Phase2 评价缺乏差异同时出现？

首个验收目标不是强制找到 27 组，而是得到一份能够区分“Phase2 前抽样偏差”“支持内系数选择偏差”“精确预算支持拥挤”和“当前证据仍不足”的可重算报告。

## 3. 范围与不变量

### 3.1 允许修改

- 新增一个研究测试侧的候选快照、支持分桶和评价计划组件；
- 新增该组件的快速确定性单元测试；
- 修改 `Djx188StructuredLocalUniverseExperimentTest`，接入全量 Phase2 和新旧策略对照；
- 新增本设计文档和必要的测试输出字段。

### 3.2 明确不修改

- 不修改 `StructuredLocalPatternUniverseBuilder` 的三层构造规则；
- 不修改 `SparseProductionNeutralMoveEnumerator` 的变量、约束、目标、no-good cut、枚举顺序和预算语义；
- 不扩大到二跳桥接或完整 7717 花型上的新搜索；
- 不修改 `Phase2SequenceGroupSolver`、`OrderCompatibilityKernelAnalyzer` 的求解语义；
- 不修改生产候选生成、列生成、Stage4、Stage5、LNS、接口或页面；
- 不读取人工花型签名、人工使用次数或到人工方案的距离；
- 不把兼容性见证固化成单花型罚分。

### 3.3 控制变量

一次实验只运行一次三层稀疏状态生成。生成结果完成去重后立刻冻结为不可变候选快照，旧策略、新策略和全量诊断必须消费同一个快照对象，不允许各自重新运行稀疏 MIP。

历史运行的 307 是本轮对照锚点，不是时间限制搜索的数学不变量。实验必须同时报告：

- 实际唯一状态数；
- 是否等于历史锚点 307；
- 如果不等于 307，标记 `CANDIDATE_SNAPSHOT_DRIFT`，不得把本次覆盖率直接与历史 307 状态运行作数值等同比较；
- 无论是否漂移，同一次运行内部的新旧策略仍共享同一快照，因此 A/B 归因仍然成立。

本轮不保存或人工拼接一份“307 状态 CSV”。上一轮没有输出全部状态，重新依赖时间限制生成后再落盘不能证明它就是原来的 307 个状态，反而会制造虚假的跨运行确定性。

## 4. 方案比较与选择

### 4.1 固化 307 状态为静态文件

优点是后续运行完全一致；缺点是上一轮没有保存全部状态，只能重新生成一批状态后冒充历史快照，而且静态文件容易与候选模型演进失配。本轮不采用。

### 4.2 单次生成、内存冻结、同池 A/B

稀疏搜索只执行一次，按最终状态签名去重，同时合并跨层来源。冻结后的不可变快照供全量 Phase2、全局状态策略和支持分桶策略共同使用。

该方案不能保证不同机器、不同运行都恰好得到 307 个状态，但能严格保证一次控制实验内部只有评价策略发生变化。它最符合本轮“冻结生成侧、只比较评价侧”的目标，作为推荐方案。

### 4.3 改成节点数或固定支持数驱动的确定性生成

可能提高跨运行可复现性，但会改变稀疏生成边界和候选分布，使本轮同时改动生成与评价两个变量。本轮不采用，后续可单独立项。

## 5. 候选快照与规范化身份

### 5.1 唯一状态集合

令三个局部层实际生成的候选并集为 `C`，按 `stateSignature` 去重后得到冻结状态集合：

```text
S = unique(C, stateSignature)
```

同一状态在多个局部层出现时只保留一个状态对象，但来源记录为全部来源层的集合，而不是只保留首次出现的层。

### 5.2 支持身份

本轮“支持”指生产中性移动的有符号非零支持，不是最终方案中全部正使用花型，也不是局部宇宙内部的整数下标集合。

支持身份由 `delta` 中所有非零项构造：

1. 负系数记为 `R:<patternSignature>`；
2. 正系数记为 `A:<patternSignature>`；
3. 分别按稳定花型签名排序；
4. 不包含系数绝对值。

因此同一组移出/移入花型上的不同整数系数状态进入同一个支持桶。不得直接使用 `SparseProductionNeutralMoveEnumerator` 内部基于局部花型下标生成的 `supportSignature` 做跨层身份，因为嵌套局部宇宙中的下标不具备全局稳定语义。

### 5.3 分母定义

全局支持分母为：

```text
U = { supportIdentity(s) | s in S }
supportDenominator = |U|
```

它不是 `121 + 370 + 1050`，也不是三层理论上可能产生的支持数。

全局统计对跨层重复支持只计一次。分层统计使用每层实际生成状态对应的支持集合独立计算；同一支持可以出现在多个分层统计中，但在全局并集中只能计一次。报告必须同时给出分子、分母和跨层重复数。

## 6. 全量 Phase2 诊断

### 6.1 单次评价与缓存

对冻结集合 `S` 中每个状态恰好调用一次现有 `ProductionNeutralMoveSearch.fastUpperBound`，结果按 `stateSignature` 缓存。任何策略只读取缓存，不得重复调用 Phase2。

每个状态记录：

- Phase2 状态；
- 组数、奇数组数、单车组数；
- 是否满足目标形态 `odd=1 && one=0`；
- 耗时；
- 全局状态排名；
- 所属支持桶和全部来源层。

### 6.2 排名语义

为避免本轮偷偷更换价值函数，状态排名沿用当前研究实验的顺序：

1. 目标形态可行优先；
2. 非负组数升序；
3. `stateSignature` 稳定排序。

`NO_SOLUTION`、`INVALID` 和 `ERROR` 不得当作不可行证明，统一排在有可行上界的状态之后，并分别计数。

### 6.3 支持内代表

每个支持桶的代表是该桶按上述同一排名得到的第一名。必须保留：

- 桶内状态数；
- 桶内可行/目标形态可行状态数；
- 最好和最差 Phase2 组数；
- 静态首状态与 Phase2 最优代表是否一致；
- 最优代表是否进入过历史前缀抽样；
- 由错误系数选择造成的组数差。

这一步只选择评价代表，不改变支持或系数状态本身。

## 7. 三种评价视图

### 7.1 历史前缀视图

复现当前实验的旧流程：先按原有静态顺序做支持多样化，再取前 `N` 个状态。该视图用于回答“有限 Phase2 前缀覆盖了多少实际支持、漏掉多少桶内最优系数状态”。

它与全量方案的 Phase2 成本不同，因此只作为历史偏差诊断，不作为同预算 A/B 的主结论。

### 7.2 `GLOBAL_STATE` 同预算策略

读取全部 Phase2 缓存，按状态全局排名，将前 `E` 个状态送入精确阈值 MIP。允许多个状态来自同一支持。这是“全量 Phase2 后仍按状态分配精确预算”的对照组。

### 7.3 `SUPPORT_BUCKET` 同预算策略

读取相同的全部 Phase2 缓存，先为每个支持选出内部最优代表，再对代表全局排名，将前 `E` 个不同支持送入精确阈值 MIP。

两种主策略必须满足：

- Phase2 调用集合完全相同，均为 `S`；
- Phase2 调用次数完全相同，均为 `|S|`；
- 精确阈值 MIP 名额相同，均为 `E`；
- 单次阈值时间、节点和配置上限相同；
- 若两个策略选中同一 `stateSignature`，精确结果按状态缓存并复用，但预算报告仍分别按策略的逻辑名额计算；
- 不因某策略先运行而获得额外见证、排序或 warm start。

## 8. 精确评价语义

每个决赛状态使用现有阈值模型检查：

```text
groups <= 27
oddGroups = 1
oneGroups = 0
```

状态解释保持不变：

- `FEASIBLE`：存在满足目标的配置组分配；随后运行完整分析并确认精确组数和形态；
- `INFEASIBLE`：该状态在完整枚举范围和求解边界内已证明不满足阈值；
- `UNKNOWN`、`ENUMERATION_LIMIT`、`SOLVER_UNAVAILABLE`、`ABNORMAL`：证据不足，不能计为不可行。

Phase2 始终只是可行上界和排序代理。即使全量 Phase2 对 307 个状态都没有给出 27 组，也不能据此证明这 307 个状态中不存在精确 27 组。只有所有状态都经过精确阈值评价并得到确定结果，才能宣称固定候选快照的精确评价已经穷尽。本轮固定精确预算较小，因此“未找到 27”通常仍应报告为 `INCONCLUSIVE`。

## 9. 指标与报告

### 9.1 候选与支持覆盖

- 原始候选数、唯一状态数、状态锚点是否漂移；
- 全局不同支持数 `|U|`；
- 每层实际状态数、不同支持数和跨层重复数；
- 历史前缀的 Phase2 状态覆盖率和支持覆盖率；
- `GLOBAL_STATE` 精确决赛状态数、不同支持数及 `不同支持数 / |U|`；
- `SUPPORT_BUCKET` 精确决赛状态数、不同支持数及 `不同支持数 / |U|`。

全量 Phase2 的支持覆盖率理论上为 100%，必须如实报告但不得把它当作策略改善。主对比指标是有限精确名额覆盖了多少不同支持。

### 9.2 Phase2 诊断

- 全量状态的 `FEASIBLE/NO_SOLUTION/INVALID/ERROR` 数量；
- 目标形态可行状态数和支持数；
- 全局最好 Phase2 组数；
- 历史前缀最好组数与全量最好组数的差；
- 每个支持的状态数分布；
- 静态首状态不是桶内 Phase2 最优代表的支持数；
- 历史前缀遗漏桶内最优代表的支持数；
- Phase2 总耗时、均值、中位数和最大耗时。

### 9.3 精确评价

每个策略分别报告：

- 名义精确预算、唯一实际求解状态数和缓存复用数；
- 不同支持覆盖数；
- `FEASIBLE/INFEASIBLE/UNKNOWN/其他` 数量；
- 是否完整分析确认不超过 27 组；
- 阈值枚举、求解和总耗时；
- 最好已确认结果。

### 9.4 主 MIP 目标分布

从已冻结的稀疏运行指标中读取每轮主 MIP 的目标值和界，输出频数分布、唯一值数量和最大同值桶。该指标只描述目标区分度现象，本轮不修改目标函数，也不提前把 `-3300` 归因到某个具体代理项。

同时把每个已生成状态关联到产生其支持的主 MIP 目标值，并按目标值输出对应 Phase2 结果的交叉分布：

- 唯一状态数和不同支持数；
- Phase2 可行及目标形态可行数量；
- Phase2 组数的最小值、中位数、最大值和频数分布；
- 同一状态跨层关联到多个不同主 MIP 目标值的数量。

种子支持没有对应主 MIP 求解目标时必须标记为 `NOT_APPLICABLE`。同一状态跨层重复生成时按全局状态签名去重；如果它在不同来源层对应不同主 MIP 目标值，必须保留全部关联并单独报告歧义，不能静默选择其中一个值。

交叉分布只用于区分两类现象：

1. 如果主 MIP 目标值高度扎堆，但对应 Phase2 组数明显分散，说明主 MIP 目标对后续价值的区分度不足；
2. 如果主 MIP 目标值和 Phase2 组数都高度扎堆，只能说明当前支持状态在两个已有代理下都高度同质，仍不能单独证明是支持结构本身导致，也不能排除两个代理同时缺少有效信号。

第二种情况不得直接写成“数学上确实同质”；只有引入独立结构特征或精确兼容性结果后才能继续归因。

## 10. 结论判定矩阵

### 10.1 Phase2 前抽样偏差已证实

满足任一条件：

- 全量 Phase2 的最好目标形态上界严格优于历史前缀；
- 历史前缀没有覆盖后来进入精确决赛的支持；
- 历史前缀遗漏多个支持桶的内部最优代表。

该结论只说明旧抽样错过了更好的 Phase2 信号。

### 10.2 支持内系数选择偏差已证实

同一支持桶内存在至少两个系数状态，且静态首状态与 Phase2 最优代表不同。若组数或目标形态严格改善，记录改善幅度。

### 10.3 精确预算支持拥挤已证实

`GLOBAL_STATE` 的 `E` 个决赛状态覆盖少于 `E` 个支持，而 `SUPPORT_BUCKET` 覆盖 `E` 个不同支持。若后者找到前者未找到的精确可行解，则可进一步证明按支持分配精确预算具有实际收益。

### 10.4 当前 Phase2 代理没有提供更强信号

全量 Phase2 最好结果不优于历史前缀，且支持内代表选择没有产生改善。该结果不能直接区分“候选生成不足”和“Phase2 代理区分度不足”，下一步应先检查 Phase2 与精确阈值结果的相关性，再决定是否扩展生成侧。

### 10.5 固定候选池不存在 27 组

只有对 `S` 中全部状态完成精确阈值评价，且全部得到确定的 `INFEASIBLE`，才能作此声明。本轮默认精确预算不满足该证明条件，因此不得预设会得到该结论。

## 11. 代码结构

推荐新增测试侧组件 `SupportBucketedCandidateEvaluator`，职责限于：

- 从三个稀疏结果构造不可变候选快照并合并来源层；
- 生成稳定支持身份和支持桶；
- 接收已计算的 Phase2 分数；
- 生成历史前缀、`GLOBAL_STATE` 和 `SUPPORT_BUCKET` 三种评价计划；
- 计算覆盖率、支持内系数差异和预算指标。

该组件不得直接构造局部宇宙、调用稀疏 MIP 或修改任何求解模型。Phase2 和精确阈值调用仍保留在 DJX188 opt-in 实验中，确保快速单元测试可以用人工分数验证纯选择语义。

新增 `SupportBucketedCandidateEvaluatorTest`，使用小型虚构候选验证规范化、去重、分桶、排名和预算，不运行长时间真实数据求解。

## 12. 测试设计

### 12.1 快速单元测试

至少覆盖：

1. 同一状态跨层出现时只保留一次并合并全部来源层；
2. 同一有符号支持、不同系数状态进入同一桶；
3. 局部下标型 `supportSignature` 不影响全局支持身份；
4. 正负方向或花型集合不同的移动不会错误合桶；
5. 全局支持分母只来自实际唯一状态；
6. 跨层支持全局只计一次、分层分别可重算；
7. 支持代表遵循目标形态、组数、状态签名的稳定顺序；
8. 无解、无效和错误 Phase2 结果排在可行结果之后；
9. `GLOBAL_STATE` 可以选择同一支持的多个状态；
10. `SUPPORT_BUCKET` 在预算允许时每个支持最多选择一个状态；
11. 两种主策略具有相同 Phase2 集合、精确名额和单次精确限制；
12. 历史前缀覆盖率使用 `|U|`，不使用三层理论花型数。

### 12.2 真实数据实验

继续使用显式系统属性开启，不进入默认 `mvn test`。真实实验必须输出本设计第 9 节全部指标，并保留原有局部宇宙构造锚点和支持搜索状态。

### 12.3 回归与构建

验证顺序：

1. `mvn -q -DskipTests test-compile`；
2. 运行 `SupportBucketedCandidateEvaluatorTest`；
3. 运行结构化局部宇宙、生产中性移动、稀疏枚举和订单兼容性核相关快速回归；
4. 使用显式开关运行 DJX188 长实验；
5. 报告实际执行、成功、失败、错误和跳过数，禁止把 `0 tests found` 或全部跳过当作通过；
6. `mvn -q -DskipTests package`；
7. `git diff --check` 并核对提交范围。

全量 Phase2 可能显著延长实验时间，实验必须持续输出进度，并单独报告 Phase2 总耗时。默认测试仍只运行快速确定性回归。

## 14. 验收标准

- 三种策略消费同一个不可变候选快照；
- 唯一状态按 `stateSignature` 去重，跨层来源不丢失；
- 支持身份不依赖局部宇宙下标或系数绝对值；
- 支持覆盖率分母严格等于固定快照实际出现的不同支持数；
- 全局去重统计和分层统计分开报告；
- 全量 Phase2 对每个唯一状态恰好调用一次；
- 主 A/B 的 Phase2 集合、精确预算和精确限制完全一致；
- 支持内最优代表和全局状态排名使用同一排序语义；
- Phase2 不被误用为不可行证明；
- 精确超时或枚举受限保持未知；
- `-3300` 只作为区分度现象记录，未经代码证据不做根因归因；
- 主 MIP 目标值与 Phase2 组数按唯一状态完成交叉分布，跨层多目标关联不被静默丢弃；
- 不修改生成侧、生产代码或两个 kernel 的判定语义；
- 默认测试入口不运行长时间研究实验；
- 无论是否找到 27 组，都按实际穷尽状态和证据边界陈述结论。
