# 订单兼容性核分析器设计

## 1. 目标

新增研究侧 `OrderCompatibilityKernelAnalyzer`，对“已经确定花型及使用次数”的方案计算订单级序号组下界。

分析器回答的是集合问题：

> 给定完整花型集合、每个花型的使用车数和逐订单需求，至少需要多少种完整单车订单配置，才能精确满足全部订单？

输出必须区分：

- 花型数；
- 订单兼容性导致的最小额外组数；
- 可行上界与已证明下界；
- 是否已经证明最优；
- 最优或当前最好拆分见证；
- 配置枚举规模、模型规模和实际耗时。

本阶段只建立研究工具和回归基线，不接入生产 bundle 生成、Stage4、Stage5、LNS 或前端链路。

## 2. 已确认基线

同一组序号组差距已经被精确拆解为：

```text
DJX188 当前结果 29
= 22 个花型
+ 6 个订单兼容性必需拆分
+ 1 个 Stage5 可恢复差距
```

独立完整配置 MIP 已得到以下证据：

- DJX188 自动 22 花型：557 种完整配置，最优 28 组，最优间隙 0；
- DJX188 人工 26 花型：存在一花型一配置的 26 组精确分配；
- T42：10 花型、10 组、45 车、奇数组 1、单车组 0。

拆分责任能够在花型之间转移。例如 1200 宽幅的拆分可以在两个 6 车花型之间转移。因此分析器不得输出可相加的“单花型碎片分数”；核心输出必须是整个花型集合的最小额外组数。

## 3. 方案比较

### 3.1 复用 Stage5 代理目标

优点是速度快、现有代码可直接调用。缺点是 Stage5 最小化的是 `花型 × 宽幅 × 订单` 分配边数量，不是完整单车配置数量，只能给出可行上界，不能证明下界。

该方案保留为未来两级评价的第一层，不作为本分析器的精确核心。

### 3.2 复用现有 Phase2 受限列池

Phase2 已经把完整单车订单配置作为列，建模方向正确。但当前每花型最多保留 40 列，而 DJX188 单花型最多存在 90 种完整配置。它可以产生更好可行解，但不能在当前容量下证明全配置最优。

该方案不用于严格回归断言。

### 3.3 对最终花型集合完整枚举并求精确 MIP

对每个已选花型枚举所有逐宽幅订单多重集，再做跨宽幅笛卡尔积，得到该花型的所有完整单车配置。随后用 MIP 联合决定每种配置使用多少车。

优点是模型语义与最终序号组完全一致，并能在求解器返回 `OPTIMAL` 时给出严格下界。缺点是最坏情况下配置数呈组合增长，只适合最终候选或小规模决赛圈。

本阶段选择该方案。未来闭环采用两级评价：Stage5/LNS 先提供廉价可行上界，只对主指标打平的少量候选调用精确分析器。

## 5. 接口设计

核心入口：

```java
static Analysis analyze(
        Map<PatternCandidate, Integer> solution,
        List<SolverOrderItem> orderItems,
        Options options)
```

`Options` 至少包含：

- 组数证明时间上限；
- 奇数/单车形态优化时间上限；
- 最大允许完整配置数；
- SCIP 节点上限，`-1` 表示不限制；
- 是否在 SCIP 不可用时回退 CBC。

`Analysis` 至少包含：

- 分析状态和求解器名称；
- `groupOptimal`：组数是否已经证明最优；
- `shapeOptimal`：在最小组数下奇数/单车形态是否完成词典序优化；
- 花型数、当前最好可行组数、已证明组数下界；
- 当 `groupOptimal=true` 时的精确最小组数和最小额外组数；
- 奇数组数、单车组数；
- 完整配置数、变量数、约束数、节点数；
- 枚举耗时、组数求解耗时、形态优化耗时和总耗时；
- 每个被拆花型的配置、配置车数及涉及订单；
- 宽幅级变化摘要，用于说明哪些宽幅/订单在不同配置间发生切换。

若只得到 `FEASIBLE`，结果必须同时返回当前可行上界和求解器 best bound，禁止把可行值命名为“精确下界”。若达到配置上限，则在建模前返回明确的 `ENUMERATION_LIMIT`，不得静默截断配置。

## 6. 完整配置枚举

### 6.1 输入校验

分析器只接受精确生产方案：

- 所有使用次数为正整数；
- 花型签名唯一；
- 订单键使用 `width + messageText`；
- 同键需求合并且必须为正；
- 花型总产量逐宽幅严格等于订单总需求。

出现超产、欠产、缺失订单宽幅或重复花型签名时直接抛出带上下文的参数异常。本阶段不把超产虚拟订单引入模型。

### 6.2 确定性顺序

- 花型按规范签名排序；
- 宽幅升序；
- 同宽幅订单按 `messageText` 排序；
- 单宽幅槽位配置使用可重复组合，不枚举槽位排列；
- 跨宽幅按固定顺序做笛卡尔积。

因此输入 Map 插入顺序不影响配置集合、模型规模和聚合指标。

### 6.3 配置含义

若花型在宽幅 `w` 上有 `k` 个槽位，则该宽幅配置是从所有 `w` 订单中选择 `k` 个消息编号的多重集。一个完整配置由花型全部宽幅的多重集共同组成。

每个完整配置对应最终序号组中的一种单车内容；同一配置连续运行多车仍只计一个组。

## 7. 精确 MIP

对每个花型 `p` 和完整配置 `c` 定义：

- `n[p,c]`：该配置使用车数，非负整数；
- `y[p,c]`：该配置是否启用，布尔变量；
- `half[p,c]`：车数的一半整数部分；
- `odd[p,c]`：该组车数是否为奇数；
- `one[p,c]`：该组车数是否恰好为 1。

约束：

```text
每花型：Σc n[p,c] = usage[p]
每订单：Σp,c contribution[p,c,order] × n[p,c] = demand[order]
启用联动：y[p,c] ≤ n[p,c] ≤ usage[p] × y[p,c]
奇偶：n[p,c] = 2 × half[p,c] + odd[p,c]
单车：当 y=1 且 one=0 时 n≥2；当 one=1 时 n=1
```

词典序求解：

1. 最小化 `Σ y[p,c]`，得到最小组数；
2. 固定最小组数，最小化 `Σ odd[p,c]`；
3. 固定最小奇数组数，最小化 `Σ one[p,c]`。

第一阶段证明最优后，即使后续形态优化超时，最小组数结论仍保持有效；结果通过 `groupOptimal` 与 `shapeOptimal` 分开表达。

## 8. 两级评价与性能边界

本阶段不把分钟级精确 MIP 放进 bundle 生成循环。未来接入遵循：

```text
主指标候选集合
  -> Stage5/LNS 快速可行上界
  -> 剔除明显更差候选
  -> 少量决赛候选运行 OrderCompatibilityKernelAnalyzer
  -> 用精确组数或 best bound 做最终判别
```

精确分析器记录完整性能证据，但测试不设置严格毫秒阈值，避免不同机器造成伪失败。性能报告必须包含配置数、变量数、约束数、节点数和分阶段耗时，后续再依据实测决定是否开发按需列生成、冲突切割或配置缓存。

## 9. 回归测试

测试类固定为 3 个测试方法，对应 3 个锚点。

### 9.1 DJX188 自动 22 花型

- 固化本轮 22 花型及使用次数，不依赖分钟级上游搜索；
- 精确满足 169 车、36,870 mm 废料、0 超产；
- 完整配置数为 557；
- 断言组数求解状态为 `OPTIMAL`；
- 断言最小组数 28、额外组数 6；
- 断言最优形态奇数组 1、单车组 0；
- 输出拆分见证和耗时基准。

### 9.2 DJX188 人工 26 花型

- 复用现有人工花型资源；
- 断言组数求解状态为 `OPTIMAL`；
- 断言最小组数 26、额外组数 0；
- 断言奇数组 1、单车组 0；
- 输出模型规模和耗时。

### 9.3 T42 10 花型

- 从已经验证的 10 花型/45 车结果固化独立测试夹具，不在本测试中重新运行完整上游求解；
- 断言组数求解状态为 `OPTIMAL`；
- 断言最小组数 10、额外组数 0；
- 断言奇数组 1、单车组 0；
- 输出模型规模和耗时。

测试结束必须报告实际执行数、成功数、失败数和跳过数。耗时只记录不设硬失败阈值。

## 10. 非目标

- 不给单个花型生成静态碎片分数；
- 不修改列生成 reduced cost；
- 不自动生成互补 bundle；
- 不替换或扩大生产 Phase2 列池；
- 不把精确分析器默认接入生产请求；
- 不支持超产订单兼容性建模；
- 不以降低奇数组为代价增加最小组数。

## 11. 验收标准

- 分析器是集合函数，接口和输出中不存在可相加的单花型评分；
- 三个回归锚点分别稳定证明 28、26、10 组；
- 自动 22 花型明确分离 6 个结构性额外组和 Stage5 的 1 组差距；
- `OPTIMAL`、`FEASIBLE`、配置上限和超时语义不混淆；
- 输出足以还原被拆花型、配置车数和订单变化；
- 输出完整模型规模与计算耗时；
- 不修改生产代码，不混入工作区已有无关改动；
- 设计提交和实现提交分离，提交信息符合中文规范。
