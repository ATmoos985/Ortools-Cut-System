# 零超产、1车组与宽度单调性阶段结论

## 1. 目标层级

生产质量档采用以下业务层级：

1. 需求精确守恒，实际超产为 0。
2. 总车数最少，等价于在固定总宽口径下优先保证得率。
3. 1车组必须优先消除。
4. 序号组最少。
5. 奇数车组达到可行下限。
6. 小车数组、花型数和废边依次作为后级指标。

配置中的 `totalOverCap` 只是搜索可行域上限，不代表允许最终结果超产。最终候选仍按实际超产量比较，T42、sixian 和 t9 本轮结果均为实际超产 0。

## 2. 已实现能力

### 2.1 统一四阶段集合划分

`UnifiedSetPartitionSolver` 的严格目标为：

`groups -> odd blocks -> one-car blocks -> small blocks`

模型为每个列使用次数增加 `count == 1` 的等价布尔变量，并支持在固定组数、奇数组上限下直接最小化 1车组。

外围 LNS/SPR 不允许用增加序号组换取减少 1车组。1车组由固定上限精修处理，避免局部搜索接受 `10组/1车1 -> 11组/1车0` 这种业务退化。

### 2.2 宽度范围单调候选

已确认 4410 的新增花型会改变 A 层路径，使 T42 从 10 组退化到 11 组。质量模式在最大宽度刚超过百位边界一个步长时，自动追加内缩一个步长的候选，并与原候选统一评优。

该机制不改变 API。前端和 APS 都只需调用统一精确解入口。标准 4400 不追加候选，快解不追加候选。可通过 `cutting.nestedWidthCandidateSteps` 显式控制。

## 3. 实测结果

| 数据集 | 结果（组/奇数/1车/小组） | 车数 | 实际超产 | 耗时 |
| --- | --- | ---: | ---: | ---: |
| T42 max=4400 | 10/1/0/8 | 45 | 0 | 47.96s |
| T42 max=4410 | 10/1/0/8 | 45 | 0 | 99.48s |
| sixian 快解 | 56/6/1/23 | 462 | 0 | 4.2s |
| sixian 精确解 | 42/2/0/11 | 462 | 0 | 174.7-198.4s |
| t9est188 精确解 | 66/8/1/27 | 530 | 0 | 480.2s |

T42 总有效宽度为 196180mm，45 车对应按 4400mm 口径的有效得率为 `196180 / (45 * 4400) = 99.08%`。

## 4. 已证伪方向

针对 t9 的唯一 1车组，以下在线后处理均未在预算内改善：

- 38853 列归档缩减到 1200 列，在 `66组/8奇数` 上限下直接最小化 1车组，60s 后仍为 1。
- 唯一 1车组加 7 个捐赠块：15 个需求键、550 列、78 车，60s 后仍为 1。
- 唯一 1车组加 9 个捐赠块：20 个需求键、1920 列、97 车，60s 后仍为 1。

因此大池 1车精修默认关闭，不能把无改善的 20-60s 机制带入生产。下一阶段应在 A 层花型选择或 Stage5 分配时前置规避该结构。

## 5. 下一阶段

1. 为 Stage5 增加可验证的 1车下界与固定上限目标，避免事后大池修复。
2. 对明显落后于当前最好组数的 parity 候选建立安全下界，减少 t9 的无效 LNS/SPR 时间。
3. sixian 和 t9 各重复至少 3 次，记录结果签名、P50/P95 和阶段耗时，再判断稳定性能。
4. 保持 CP-SAT 为确定性和最优性证明研究支线，不用架构迁移替代当前证据驱动优化。
